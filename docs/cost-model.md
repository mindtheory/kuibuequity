# 成本口径唯一说明（Cost Model）

> 上游事实源：`docs/design.md` 原则 **P4「成本口径唯一」**、`docs/interface.md` §1。
> 本文是**全系统唯一的成本口径文档**：所有金额计算一律经 `src/costs.js`，
> 任何模块（策略/回测/账本/指令单）**禁止自行定义费率或重复计费**。
>
> 费率均为 **2026 口径的公开规则**，实际以用户券商交割单为准；
> 差异通过 `DEFAULT_FEE` 覆盖，不允许在代码里硬编码第二套费率。

---

## 1. A 股现行费率表（2026 口径）

| 项目 | 方向 | 费率 | 代码字段 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 佣金 | 双向 | 万 2.5（0.025%），**单笔最低 5 元** | `commissionRate` / `commissionMin` | 券商可谈（万 1～万 3），以开户协议为准；最低佣金是小额单的主要杀手 |
| 印花税 | **仅卖出** | 万 5（0.05%） | `stampTaxRate` | 2023-08-28 起由千 1 减半至万 5，2026 年沿用；买入不收 |
| 过户费 | 双向 | 万 0.1（0.001%） | `transferRate` | 2022-04-29 起由万 0.2 降至万 0.1，沪深两市均收 |
| 滑点 | 双向 | 0 bp（默认） | `slippageBps` | 仅回测/模拟盘使用；实盘由真实成交价体现，不重复计 |

对应 `interface.md` §1 的 `DEFAULT_FEE`：

```js
{ commissionRate: 0.00025, commissionMin: 5, stampTaxRate: 0.0005,
  transferRate: 0.00001, slippageBps: 0 }
```

### 1.1 单笔费用公式（`tradeFee`）

```
amount     = price × qty
commission = max(amount × commissionRate, commissionMin)
stampTax   = (side == 'sell') ? amount × stampTaxRate : 0
transfer   = amount × transferRate
tradeFee   = round2(commission + stampTax + transfer)
```

- 返回值单位 **元**，保留 **2 位小数**（`round2` 采用四舍五入 + EPSILON 修正）。
- `price ≤ 0` 或 `qty ≤ 0` 或 `side ∉ {buy, sell}` → 抛 `ERR-COST-001/002`（诚实失败，P6）。
- **最低佣金按单笔计算**：拆单会抬高成本，这是"网格每格别太小"的直接原因。

### 1.2 费用占比与最低佣金的临界点（可验算）

| 单笔金额 | 佣金（万 2.5） | 实际佣金率 | 备注 |
| :-- | :-- | :-- | :-- |
| 1,000 元 | max(0.25, 5) = **5.00** | 0.500% | 最低佣金生效，费率是标准的 20 倍 |
| 5,000 元 | max(1.25, 5) = **5.00** | 0.100% | 仍被最低佣金支配 |
| **20,000 元** | max(5.00, 5) = **5.00** | 0.025% | **临界点**：`5 / 0.00025 = 20,000` |
| 50,000 元 | 12.50 | 0.025% | 正常费率 |
| 200,000 元 | 50.00 | 0.025% | 正常费率 |

> 结论：**单笔 < 2 万元的交易，佣金率被最低 5 元抬高**。
> 稳定象限 25,000 元级别、长期象限每格 5,400 元级别都会踩到最低佣金，
> 因此两者的算法文档里都做了"含费盈亏比 / 单格净收益"的验算。

### 1.3 双边总成本速查

```
买入成本率 ≈ 0.025%（佣金，≥最低5元） + 0.001%（过户费）           = 0.026%
卖出成本率 ≈ 0.025% + 0.05%（印花税） + 0.001%                    = 0.076%
一买一卖合计 ≈ 0.102%（不含最低佣金抬高、不含滑点）
```

含滑点时（`slippageBps` 双边各计一次）：`0.102% + 2 × slippageBps/10000`。
例：`slippageBps = 10`（10bp）→ 双边合计 `0.102% + 0.20% = 0.302%`。

## 2. 含滑点的成交价（`applySlippage`）

```
buy :  execPrice = round3(price × (1 + slippageBps / 10000))
sell :  execPrice = round3(price × (1 − slippageBps / 10000))
```

| 输入 | 计算 | 结果 |
| :-- | :-- | :-- |
| 买入 6.10，slippageBps=10 | 6.10 × 1.001 | 6.106 |
| 卖出 6.10，slippageBps=10 | 6.10 × 0.999 | 6.094 |
| 买入 6.10，slippageBps=0 | 6.10 | 6.100 |

**使用边界**：

- 滑点**只用于回测与模拟盘（L2）**，代表"你实际会成交在什么价"。
- 实盘指令单（L0/L1）给出的是**委托价**，不再叠加滑点，否则等于双重惩罚。
- 涨跌停场景不用滑点近似：一字涨停买不进、跌停卖不出，直接判不成交（见 `data-sources.md` §5）。

## 3. 有效持仓成本 `holdingCost` —— 全系统唯一口径

### 3.1 定义

```
totalIn        = Σ(买入金额) + Σ(买入费用)
totalRecovered = Σ(卖出金额) − Σ(卖出费用) + Σ(每股分红 × 除息日当时持股数)
netInvested    = totalIn − totalRecovered
costPerShare   = netInvested / shares            （shares = 0 → null）
negative       = costPerShare ≤ 0
avgEntryPrice  = Σ(买入金额) / Σ(买入股数)        （不含费用；无买入 → null）
progress       = clamp(1 − costPerShare / avgEntryPrice, 0, 1)
```

**语义**：`costPerShare ≤ 0` ⟺ 累计已回收现金 ≥ 累计总投入。
此时该标的**任何价格卖出都是纯赚**（本金已通过分红与网格价差收回）。
这是长期象限唯一 KPI（design.md §4.1）。

### 3.2 逐步推导（为什么是这个形式）

| 步骤 | 处理 | 理由 |
| :-- | :-- | :-- |
| ① 买入 | `totalIn += price×qty + fee` | 费用是真金白银流出，必须进成本，否则与交割单对不上 |
| ② 卖出 | `totalRecovered += price×qty − fee` | 卖出是现金回流，净额才等于"真正拿回来的钱" |
| ③ 分红 | `totalRecovered += dividendPerShare × shares@exDate` | 分红是现金回流，**但不经过交易**，只能单独入账 |
| ④ 份额 | `shares += qty(buy)` / `shares −= qty(sell)` | 卖出超过持股 → `ERR-COST-005`（流水不闭合，拒绝计算） |
| ⑤ 相除 | `costPerShare = (totalIn − totalRecovered)/shares` | 把"已回收"摊到**剩余**持股上，才叫"有效成本" |
| ⑥ 进度 | `1 − costPerShare / avgEntryPrice` | 分母用**建仓加权均价**（不含费用），使 progress=0 对应"刚建仓未回收" |

### 3.3 分红入账规则（最容易算错的地方）

| 规则 | 内容 | 错误做法 |
| :-- | :-- | :-- |
| **入账时点** | **除息日（exDate）当天**，不是股权登记日、不是到账日 | 按到账日入账 → 与除息跳空错位 |
| **计算基数** | **除息日当时的持股数**（`shares@exDate`） | 用当前持股数回溯 → 期间卖出的部分被重复计息 |
| **金额** | 每股现金分红（**含税口径**，A 股个人持股 >1 年免个税，1 个月内 20%、1 个月内至 1 年 10%） | 忽略税差 → 高估回收 |
| **与复权的关系** | 指标用**前复权**价格（已抹平除息跳空），分红**单独入账一次**，两者不重复 | 前复权价 + 分红双计 → 成本被压低两次（虚高 progress） |
| **送股/转增** | 增加 `shares`，不产生现金 → 体现在流水的 qty，不进 `totalRecovered` | 当分红计 → 虚增回收 |
| **派息税差** | 若需精确，`dividendPerShare` 传**税后**值；默认按免税（长期持有）口径 | 混用含税/税后 |

> **实现约定（重要）**：`interface.md` §1 的 `lots` 行结构为
> `{ date, side:'buy'|'sell', price, qty, fee, dividend? }`，
> 分红通过某行的 `dividend`（每股金额）表达，`src/costs.js` 在**处理完该行份额变动后**入账。
> 因此 ledger 必须把分红挂到**除息日时点持股数已确定的那一行**（即除息日之前最后一笔流水），
> 这样 `shares` 恰好等于 `shares@exDate`。
> 「分红作为独立事件入参」属**计划**改造（见 §6 澄清项），改造前请按本约定调用。

### 3.4 progress 的边界与语义

| 情形 | progress | 说明 |
| :-- | :-- | :-- |
| `shares = 0`（已清仓） | 0 | `costPerShare = null`，进度无意义；清仓后应看"现金回收率 = totalRecovered/totalIn" |
| `avgEntryPrice ≤ 0` 或 null | 0 | 无买入流水 |
| `costPerShare > avgEntryPrice`（费用/税吃掉回收） | clamp 到 0 | 不会出现负进度 |
| `costPerShare = 0` | 1 | 成本归零 |
| `costPerShare < 0` | clamp 到 1 | 已转负，进度封顶 100% |

### 3.5 成本转负 ETA（`costToNegativeEta`）

**年化摊薄率**（`annualDilutionRate`）：

```
annualDilutionRate = dividendYield + floatWeight × gridAnnualGross − costDrag
```

**ETA（线性现金回收解）**：

```
每年回收现金 = price × annualDilutionRate × shares
ETA(年)      = costPerShare × shares / 每年回收现金
             = costPerShare / (price × annualDilutionRate)
```

**边界（必须返回 null，不得伪造）**：

| 输入 | 返回 | 理由 |
| :-- | :-- | :-- |
| `costPerShare ≤ 0` | `0` | 已转负，无需等待 |
| `annualDilutionRate ≤ 0` | **`null`** | 无摊薄来源（不分红 + 网格停摆）→ 诚实拒绝（P6），绝不给"很久以后"这种模糊答案 |
| `price ≤ 0` 或 `costPerShare` 非有限数 | `null` | 参数非法 |
| `annualDilutionRate` 缺失/NaN | `null` | 同上 |

**模型假设与局限（必须向用户说明）**：

1. 假设**价格不变**、分红率不变、网格年化毛收益不变 —— 现实里三者都会变。
2. 线性口径下 ETA 与 `costPerShare` 成正比；分红再投会**延长** ETA（现金又变回股票）。
3. `gridAnnualGross` 必须来自回测或实盘统计，**不允许拍脑袋填**；填 0 即退化为"纯分红 ETA"。
4. design.md §4.5 的对数式在 `costPerShare > 0` 时分子为负、结果恒负，**不可用**；
   本文与实现采用线性解（差异已登记，见 §6）。

## 4. 手算示例：5 笔流水（含 1 次分红、1 次部分卖出）

标的 600xxx，费率用 `DEFAULT_FEE`。事件按时间顺序：

| # | 日期 | 事件 | 价格 | 数量 | 成交金额 | 费用明细 | 费用 | 持股数 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 2026-03-02 | 买入 | 7.00 | 5,000 | 35,000.00 | 佣金 8.75 + 过户 0.35 | **9.10** | 5,000 |
| 2 | 2026-04-15 | 买入 | 6.50 | 3,000 | 19,500.00 | 佣金 max(4.875,5)=5.00 + 过户 0.195 | **5.20** | 8,000 |
| 3 | 2026-06-20 | **除息**：每股派 0.30 | — | — | — | 现金 = 0.30 × 8,000 | **+2,400.00**（回收） | 8,000 |
| 4 | 2026-08-10 | **部分卖出** | 7.20 | 3,000 | 21,600.00 | 佣金 5.40 + 印花税 10.80 + 过户 0.216 | **16.42** | 5,000 |
| 5 | 2026-09-18 | 买入 | 6.80 | 2,000 | 13,600.00 | 佣金 max(3.40,5)=5.00 + 过户 0.136 | **5.14** | 7,000 |

### 4.1 逐项费用验算

```
#1 佣金 35,000×0.00025 = 8.750 > 5 → 8.75；过户 35,000×0.00001 = 0.350 → 合计 9.100 → 9.10
#2 佣金 19,500×0.00025 = 4.875 < 5 → 5.00；过户 0.195 → 合计 5.195 → 5.20
#4 佣金 21,600×0.00025 = 5.400 → 5.40；印花税 21,600×0.0005 = 10.800；过户 0.216
   → 合计 16.416 → 16.42
#5 佣金 13,600×0.00025 = 3.400 < 5 → 5.00；过户 0.136 → 合计 5.136 → 5.14
```

### 4.2 传给 `holdingCost` 的 `lots`

分红按 §3.3 约定挂在**除息日时点持股数已确定的行**（此处为 #2，处理后 `shares = 8,000`）：

```js
lots = [
  { date:'2026-03-02', side:'buy',  price:7.00, qty:5000, fee:9.10  },
  { date:'2026-04-15', side:'buy',  price:6.50, qty:3000, fee:5.20, dividend:0.30 },
  { date:'2026-08-10', side:'sell', price:7.20, qty:3000, fee:16.42 },
  { date:'2026-09-18', side:'buy',  price:6.80, qty:2000, fee:5.14 },
]
```

### 4.3 中间量（逐步累加，可逐行核对）

| 步骤 | 动作 | totalIn | totalRecovered | dividends | shares |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 初始 | — | 0.00 | 0.00 | 0.00 | 0 |
| #1 | 买 5,000 | 35,009.10 | 0.00 | 0.00 | 5,000 |
| #2 | 买 3,000 | 54,514.30 | 0.00 | 0.00 | 8,000 |
| #2′ | 分红 0.30×8,000 | 54,514.30 | 2,400.00 | 2,400.00 | 8,000 |
| #4 | 卖 3,000（净 21,583.58） | 54,514.30 | 23,983.58 | 2,400.00 | 5,000 |
| #5 | 买 2,000 | 68,119.44 | 23,983.58 | 2,400.00 | 7,000 |

```
totalIn        = 35,009.10 + 19,505.20 + 13,605.14 = 68,119.44
卖出净额        = 21,600.00 − 16.42 = 21,583.58
totalRecovered = 2,400.00 + 21,583.58 = 23,983.58
netInvested    = 68,119.44 − 23,983.58 = 44,135.86
```

### 4.4 结果

```
shares         = 7,000
costPerShare   = 44,135.86 / 7,000 = 6.305123 → 6.305
avgEntryPrice  = (35,000 + 19,500 + 13,600) / 10,000 = 68,100 / 10,000 = 6.810
progress       = 1 − 6.305 / 6.810 = 1 − 0.925844 = 0.074156 → 7.42%
negative       = false
现金回收率      = 23,983.58 / 68,119.44 = 35.21%
```

**解读**：

- 分红 + 部分卖出共回收 23,983.58 元，占总投入 35.21%，但**剩余 7,000 股的有效成本仍为 6.305 元**（低于加权买入均价 6.810，摊薄 7.42%）。
- 若现价 6.10：市值 42,700.00，相对有效成本浮亏 `42,700 − 44,135.86 = −1,435.86` 元 —— 注意**浮亏不等于亏损**，已回收的 23,983.58 元现金是真实的。
- 若现价涨到 6.305 以上，账面即为"已回本"（含费口径）。

### 4.5 同一账户的 ETA

假设：现价 6.10、近 5 年平均股息率 5.5%、活动仓占比 0.30、网格年化毛收益 15%、成本拖累 0.6%。

```
annualDilutionRate = 0.055 + 0.30 × 0.15 − 0.006 = 0.094
每年回收 = 6.10 × 0.094 × 7,000 = 0.5734 × 7,000 = 4,013.80 元
ETA      = 44,135.86 / 4,013.80 = 10.996 → 11.00 年
```

反例（边界）：若该标的停止分红且网格停摆 → `annualDilutionRate = 0 − 0.006 = −0.006 ≤ 0`
→ `costToNegativeEta` 返回 **`null`**，输出提示"无摊薄来源，本标的无法成本转负"。

## 5. 与交割单对账（可核对性要求）

| 对账项 | 插件字段 | 交割单对应 | 容差 |
| :-- | :-- | :-- | :-- |
| 成交金额 | `price × qty` | 成交金额 | 0（应完全一致） |
| 佣金 | `commission` | 佣金 | ±0.01 元（四舍五入） |
| 印花税 | `stampTax` | 印花税 | 0 |
| 过户费 | `transfer` | 过户费/其他费 | ±0.01 元 |
| 现金分红 | `dividends` | 红利入账 | 税差需按实际持股期限调整 |

对不上时的处理顺序：① 核对券商佣金率与最低佣金 → ② 核对是否有规费/经手费单独列示 →
③ 核对分红税差（持股期限）→ ④ 仍不符则**以交割单为准**，用 `fee` 覆盖值逐笔回填，不改代码。

## 7. 禁止清单（评审红线）

| 禁止 | 原因 |
| :-- | :-- |
| 在策略/回测里写 `price*qty*0.00025` 之类的硬编码费率 | 违反 P4，口径漂移 |
| 前复权价格 + 分红**双重**摊薄成本 | 同一笔分红计两次，progress 虚高 |
| 用当前持股数回溯历史分红 | 期间卖出的部分被重复计息 |
| 把送股/转增当现金分红 | 无现金流入 |
| 忽略最低佣金（小额单按万 2.5 算） | 低估成本，网格/稳定象限结论失真 |
| 实盘委托价再叠加滑点 | 双重惩罚 |
| `annualDilutionRate ≤ 0` 时给一个"很大的年数" | 违反 P6，必须 `null` |
| 用 `costPerShare` 判断"该不该止损" | 它是**核算口径**，不是**决策依据**；止损看契约价 |
