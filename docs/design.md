# 跬步量化（kuibuequity）总体设计

> 不积跬步，无以至千里。
>
> 本插件的目标不是帮用户"暴富"，而是帮**普通人**把股票账户管起来：
> 用写死的规则替代临场的冲动，用可核对的账本替代模糊的记忆。

版本：v0.1.0（设计基线）　状态：设计冻结（Design Frozen）　最后更新：2026-11-22

---

## 0. 一句话定位

**跬步量化是一个"纪律执行器"，不是"预测器"。**

它把投资拆成三种互不混淆的玩法，每种玩法配一套事前写死、事中不可临时更改、事后可复盘的规则；
插件负责计算、生成指令单、盯住红线，人只负责在开盘时把指令单敲进券商。

| 象限 | 代号 | 一句话 | 收益来源 | 周期 | 主要敌人 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 长期 | `long` | 高股息底仓 + 网格摊薄，把持仓成本做成**负数** | 分红 + 网格价差 | 年（3～10 年） | 下跌时的恐慌加仓失控 |
| 稳定 | `stable` | 赚 1%～5% 就走，不猜顶 | 高频小额止盈的复利 | 日～周（≤20 交易日） | 贪婪（不落袋）与不甘（不止损） |
| 短线 | `short` | 赌次日涨停/大涨，**最多拿 5 天** | 强势延续的概率差 | 1～5 交易日 | 上头、把短线套成"长线" |

三个象限**资金账户物理隔离**（见 §6.3），一笔钱只能属于一个象限，禁止跨象限"救火"。

## 1. 设计原则（不可妥协项）

| # | 原则 | 具体含义 | 违反后果 |
| :-- | :-- | :-- | :-- |
| P1 | **只读 + 模拟 + 人工执行** | 不接任何券商交易接口、不碰资金账户、不存储任何券商凭据。插件只产出"指令单"，由人手动下单 | 直接拒绝实现 |
| P2 | **纯函数内核** | 指标、成本、回测、策略信号全部是不依赖 DSH / 不依赖网络的纯函数，可用 `node --test` 独立验证 | 代码评审打回 |
| P3 | **无未来函数** | 信号在第 i 根 K 线**收盘后**确认，订单在**第 i+1 根**开盘/收盘成交；任何用 `bars[i+1]` 决定 `bars[i]` 动作的代码视为 bug | 回测结果作废 |
| P4 | **成本口径唯一** | 佣金/印花税/过户费/滑点只在 `src/costs.js` 定义一次，全系统共用；长期模式的"成本转负"必须与真实交割单可逐笔对账 | 数值不可信 |
| P5 | **事前承诺 > 事中判断** | 建仓时锁定的止盈/止损/期限，中途修改必须显式 `override` 并填写理由，全部写审计日志 | 拒绝执行 |
| P6 | **诚实的失败** | 数据不足、停牌、涨跌停无法成交、样本外胜率不达标时，工具**明确拒绝**并说明原因，绝不伪造成交或给出"看起来能用"的建议 | 视为最高级 bug |
| P7 | **每个输出带 as_of** | 所有行情/建议都带数据时间戳与"非投资建议"脚注；数据陈旧（>1 交易日）必须显式标注 | 输出不合格 |

### 1.1 关于"自动交易"的边界（重要）

用户诉求里写明"稳定模式采用自动交易，避免人性影响收益"。本插件对"自动"的定义分三层，**只实现到 L2**：

| 层级 | 名称 | 谁下单 | 本插件 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| L0 | 建议单 | 人（看着建议手动下单） | ✅ 实现 | 收盘后生成次日指令单 |
| L1 | 条件单 | 券商（人预先挂到价触发单） | ✅ 实现 | 导出券商条件单参数：触发价/委托价/数量/有效期，人一次性挂好 |
| L2 | 模拟盘 | 插件（paper broker 自动撮合） | ✅ 实现 | 用真实行情撮合虚拟成交，验证纪律是否真能赚钱 |
| L3 | 实盘自动 | 券商 API / 量化柜台 | ❌ 不做 | 个人无资质、接口不开放、合规与资金风险不可控 |

**设计立场**：真正对抗人性的不是"机器替你下单"，而是"你在冷静时已经替冲动的自己下好了单"。
L1 条件单在 A 股散户场景下已经能覆盖止盈/止损的 95% 需求，且零合规风险。
若未来要接实盘，必须走独立的 `kuibuequity-broker` 插件、独立审计，本仓库不预留任何资金侧接口。

## 2. 在 DSH 中的形态

依据《个人量化dsh插件》的三条决策点：

| 决策点 | 选择 | 理由 |
| :-- | :-- | :-- |
| 插件形态 | **函数形态**（`export name/inject/Config/apply`） | 不向其他插件提供服务，无需 `extends Service` |
| 能力落点 | **全部注册为 Tool**（`ctx.tools.register(defineTool(...))`） | 调用方是 AI 模型：让模型能查行情、算网格、出指令单 |
| 分发单元 | npm 包 + `dsh.bundle.patch` → `cordis.patch.yml` | 与 `dsh-super-agents` 同构，`dsh plugin add kuibuequity` 即装 |

## 3. 统一内核：五段流水线

三种模式共用同一条流水线，只是各段实现不同：

```
   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌───────────┐   ┌─────────┐
   │ 行情/账本 │ → │ 策略信号  │ → │ 风控闸门  │ → │ 指令单     │ → │ 复盘     │
   │ market    │   │ strategy │   │ risk     │   │ OrderPlan │   │ review  │
   │ ledger    │   │ .evaluate│   │ .gate    │   │ .render   │   │         │
   └──────────┘   └──────────┘   └──────────┘   └───────────┘   └─────────┘
                        ↑               ↓ 拒绝
                   事前契约(contract)  REJECTED + 原因码
```

### 3.1 统一策略接口（详见 `docs/interface.md`）

```js
// 每个策略模块导出同一形状
export const meta = { mode: 'long'|'stable'|'short', name, horizon, ... };

/**
 * @param {object} input
 * @param {Bar[]}   input.bars       已复权日线，升序，最后一根 = as_of 当日
 * @param {Position|null} input.position  当前持仓（无则 null）
 * @param {Account} input.account    象限账户（现金/额度/连亏计数）
 * @param {object}  input.config     合并后的策略参数
 * @returns {{ signals: Signal[], plan: OrderPlan, diagnostics: object }}
 */
export function evaluate(input) { ... }
```

### 3.2 数据契约（核心类型）

```js
// 已复权日线（前复权）；null 值表示该处不可计算，长度与输入对齐
Bar = {
  date: 'YYYY-MM-DD', open, high, low, close, volume /* 股 */, amount /* 元 */,
  adjClose,                 // 前复权收盘（指标计算一律用这个）
  limitUp: bool, limitDown: bool,   // 当日是否封死涨停/跌停
  suspended: bool,          // 停牌
  dividendPerShare: number, // 每股现金分红（除息日当天 >0）
}

Signal = {
  mode, symbol, action: 'buy'|'sell'|'hold'|'stop_loss'|'take_profit',
  qty /* 股，整手 */, price /* 建议委托价 */, reason /* 人类可读 */,
  rule /* 触发的规则码，如 STABLE.TP_HIT */, confidence /* 0..1 */,
  asOf /* ISO 时间 */
}

OrderPlan = {
  planId, mode, asOf, tradingDay /* 指令单生效交易日 */,
  orders: [{ symbol, side, qty, price, priceType:'limit'|'market',
             condition /* 条件单触发价，可空 */, note }],
  rejected: [{ symbol, rule, reason }],   // 被风控挡下的，必须留痕
  footnotes: string[]                     // as_of、数据陈旧、非投资建议
}
```

**整手约束**：A 股买入必须 100 股整数倍（科创板 200 股起），卖出可零股。
所有 `qty` 在 `plan.js` 里统一向下取整到手，不足 1 手直接进 `rejected`。

## 4. 长期象限：股息网格 · 成本转负引擎

### 4.1 目标函数

不是"涨多少"，而是**把有效持仓成本压到 0 以下**。定义（口径详见 cost-model.md）：

```
有效成本 costPerShare = (Σ买入金额 + Σ买入费用 − Σ卖出金额 + Σ卖出费用 − Σ现金分红) / 当前持股数
```

`costPerShare ≤ 0`  ⟺  累计已回收现金 ≥ 累计总投入。此时该标的**任何价格卖出都是纯赚**，
即"用分红和网格把本金先拿回来"。工商银行这类标的正是这条路的典型：
高股息（近年股息率 5%+）、低波动、连续分红 15 年以上。

### 4.2 双仓结构

```
总仓位 = 底仓 core (默认 70%)  +  活动仓 float (默认 30%)
         │                          │
         └ 只买不卖（除分红再投）      └ 网格高抛低吸，赚价差摊薄
```

- **底仓**：只在建仓期买入，之后仅因分红/基本面变化而动。它保证"涨上去不踏空"。
- **活动仓**：网格执行体。它保证"跌下来有得赚、震荡也能摊薄"。

### 4.3 网格参数生成

```
基准价 P0 = median(近 60 交易日收盘)          // 抗单日异动
步长   g  = clamp(ATR20% × 1.2, 3%, 8%)      // 波动越大格子越宽
每格量 q  = floor(活动仓预算 / 格数 / P0 / 100) × 100   // 整手
格数   N  = 上下各 5 格（可配 3~8）
```

触发规则（收盘确认、次日执行，遵守 P3）：

```
若 前收 ≤ P0 × (1 − g×k) 且 未持满 → 买入 q 股   （k = 1..N，取最深未成交格）
若 前收 ≥ P0 × (1 + g×k) 且 活动仓 > 0 → 卖出 q 股
成交后 P0 重置为成交价（锚定跟随，避免格子越拉越偏）
```

### 4.4 分红处理

除息日：`dividendPerShare > 0` → 现金分红计入"已回收"（分子减少），
价格用前复权序列，避免除息跳空被误判为网格信号。
分红再投**默认关闭**（因为目标是把成本压负，现金回收比再投更快见效），可配 `reinvest: true`。

### 4.5 成本转负 ETA（本象限的招牌输出）

给定历史分红率 `d`（近 5 年平均股息率）、网格年化毛收益 `g_annual`、活动仓占比 `w`：

```
年化摊薄率 ≈ d + w × g_annual − 交易成本拖累
ETA(年) ≈ ln(1 − costPerShare/现价) / ln(1 + 年化摊薄率)   // 使 costPerShare → 0
```

输出示例：`工商银行 601398：当前成本 5.82，现价 6.10，年化摊薄 9.4%，预计 3.7 年成本转负`。
这是给用户看的"千里之外的跬步"，也是长期象限唯一该追的 KPI。

### 4.6 长期象限的风控红线

| 红线 | 触发 | 动作 |
| :-- | :-- | :-- |
| 单边下跌熔断 | 现价 < P0 × (1 − g×N)（网格打满） | **停止加仓**，只卖不买，转人工复核 |
| 基本面恶化 | 连续 2 年扣非亏损 / 股息率同比降 >40% / 被 ST | 冻结网格，降级为"只出不进" |
| 象限仓位 | 单票 > 长期账户 40% | 拒绝买入指令 |
| 停牌 | `suspended` | 当日全部指令转 rejected，不伪造成交 |

## 5. 稳定象限：1%～5% 反人性止盈纪律

### 5.1 问题定义

"赚 1~5% 就抛"在数学上极其简单，在人性上极其困难：
涨了想再涨（贪），跌了不肯认（不甘），空仓手痒（躁）。
所以本象限的**全部设计都在制造摩擦**：让冲动变贵，让纪律变自动。

### 5.2 止盈目标自适应（不是拍脑袋定 3%）

```
日波动率 vol = ATR14 / close
目标   t = clamp(2.0 × vol, 1%, 5%)
止损   s = −0.8 × t          // 盈亏比 1.25 : 1
时间止损 D = 15 交易日        // 到期未触发即平仓，释放资金效率
```

低波动的银行股 → t 贴近 1%，靠周转率赚钱；高波动的题材股 → t 到 5%，但**仓位必须缩小**：

```
单票仓位 = 象限资金 × riskPerTrade / |s|     // 每笔最大亏损固定为账户的 riskPerTrade（默认 1%）
```

这条公式是整个稳定象限的骨架：**目标收益与仓位反向联动**，杜绝"高波动票重仓"这一散户头号死法。

### 5.3 入场条件（择时，宁缺毋滥）

全部满足才生成买入指令：

1. 大盘过滤：沪深 300 收盘 > 其 20 日均线（弱市不做）
2. 个股趋势：`close > MA60` 且 `MA20 斜率 > 0`
3. 回调企稳：近 5 日出现 `close < MA20` 后重新站回，且当日收阳
4. 量能：当日量比 ∈ [0.8, 3.0]（缩量企稳或温和放量）
5. 流动性：日均成交额 > 5000 万，非 ST，非次新（上市 >120 日）

### 5.4 反人性机制（本象限的灵魂）

| 机制 | 做法 | 对抗的人性 |
| :-- | :-- | :-- |
| **事前契约** | 建仓时写入 `contract{t, s, D}`，锁定不可改；改需 `override + reason`，写审计 | 盘中改止盈 |
| **条件单前置** | 建仓当日就生成止盈/止损两张条件单参数，一次挂好 | 盯盘时改主意 |
| **单一决策窗** | 只在收盘后生成次日计划；盘中只允许触发已挂条件单 | 盘中追涨杀跌 |
| **冷静期** | 平仓后同标的 3 个交易日内禁止再入 | 不服气反复做同一票 |
| **连亏熔断** | 连续 4 笔亏损 或 周回撤 >3% → 本象限停 5 交易日 | 上头加倍下注 |
| **强制记录** | 每次 override 必须写理由，复盘时逐条列出 | 事后不认账 |

### 5.5 期望值自检（拒绝骗自己）

稳定象限盈亏比固定 1.25:1，故**胜率必须 > 44.4% 才是正期望**。
回测/实盘统计若滚动 50 笔胜率 < 45%，`kb_stable` 直接返回：

```
verdict: "NOT_RECOMMENDED"
reason: "近 50 笔胜率 41.2% < 盈亏比要求的 44.4%，当前市场状态下该纪律为负期望，建议停用本象限"
```

这是 P6（诚实的失败）的硬实现：**工具会拒绝帮用户做一件数学上亏钱的事**。

## 6. 短线象限：次日强势打分 · ≤5 日强制离场

### 6.1 边界声明（先说清楚它不是圣杯）

"预测次日涨停"是**概率游戏 + 极快衰减的样本外表现**。插件的定位是：
把"凭感觉打板"变成"有打分、有仓位上限、有强制离场、有胜率考核"的可控赌博，
并在胜率不达标时**拒绝下注**。任何声称稳定预测涨停的设计都是欺诈，本设计不做。

### 6.2 候选池构建（收盘后）

```
纳入：当日 涨停 | 涨幅 ≥5% | 换手率 ≥5% | 量比 ≥2
剔除：ST/*ST、上市 <60 日、流通市值 <30 亿、日均成交额 <1 亿、
      当日一字涨停（买不到，P6 不伪造成交）、已停牌
```

### 6.3 打分卡（0～100，权重可配）

| 因子 | 权重 | 打分依据 |
| :-- | :-- | :-- |
| 封单强度 | 20 | 封单额 / 流通市值；>3% 满分，炸板 0 分 |
| 涨停时间 | 15 | 一字/早盘板 > 午后板 > 尾盘板 |
| 连板高度 | 15 | 首板/二板最优；4 板以上递减（高位风险溢价） |
| 量能结构 | 12 | 换手 5%~15% 为佳；缩量板 > 天量板 |
| 板块效应 | 15 | 同板块涨停家数 ≥3 才给分（题材确认） |
| 资金流 | 10 | 主力净流入 / 成交额 |
| 大盘情绪 | 13 | 指数在 5 日线上方 + 昨日涨停股今日平均溢价（赚钱效应） |

**情绪冰点总闸**：若"昨日涨停今日平均溢价 < 0" 且 "炸板率 > 40%" → 情绪退潮，
**整个短线象限当日空仓**，不输出任何买入指令。这条比任何个股打分都优先。

### 6.4 离场规则（写死，无例外）

```
T+1 卖出规则下最早次日可卖：
  · 次日竞价高开 >3% 且开盘 5 分钟不破开盘价 → 持有观察
  · 次日涨停 → 持有至开板，开板即卖（不赌连板）
  · 冲高回落跌破开盘价 → 减仓 50%
  · 浮亏 ≤ −3% → 无条件止损（条件单前置）
  · 第 5 个交易日收盘前 → 无条件清仓（硬约束，不可 override）
```

### 6.5 仓位与准入

- 单票 ≤ 短线账户 20%；同日新开仓 ≤ 2 只；短线账户 ≤ 总资金 20%
- 滚动 30 笔胜率 < 45% **或** 期望收益 ≤ 0 → `verdict: NOT_RECOMMENDED`，象限停用
- 5 日强制离场**不接受 override**（唯一硬红线），因为它是区分"短线"与"套牢"的唯一边界

### 6.6 三象限资金隔离

```
总资金
├── long   账户  默认 60%   （高股息底仓，几乎不动）
├── stable 账户  默认 30%   （纪律止盈，中频）
└── short  账户  默认 10%   （强制离场，高频，可全损也不心疼）
```
账本按 `quadrant` 分账，跨象限调拨需显式 `transfer` 并写审计。
"短线套了拿长期的钱补" —— 账本层面直接拒绝。

## 7. 回测引擎

| 规则 | 实现 |
| :-- | :-- |
| 无未来函数 | 信号在 bar i 收盘确认，成交在 bar i+1 开盘（或收盘，可配） |
| T+1 | 当日买入不可卖；`short` 象限额外受 5 日硬期限约束 |
| 涨跌停 | 一字涨停不成交；涨停买入按涨停价；跌停卖出不成交 |
| 整手 | 买入向下取整到 100 股 |
| 成本 | 佣金（万 2.5，最低 5 元）+ 印花税（卖出万 5）+ 过户费（万 0.1）+ 滑点（可配 bp） |
| 停牌 | 跳过，不产生成交 |
| 分红 | 除息日现金入账，价格用前复权 |

**必报指标**：总收益率、年化收益、最大回撤、夏普（rf=0）、交易次数、胜率、盈亏比、
平均持仓天数、费用占比、**成本转负进度**（长期象限）。
输出为结构化 JSON，便于模型直接解读。

## 9. 数据层

首选**东方财富免 Key 公开接口**（国内直连、无需注册），备选 AkShare/Tushare（需 Token）。
详细端点、字段映射、限频与降级策略见 `docs/data-sources.md`。

数据质量硬要求（否则回测失真）：
1. **复权**：指标计算统一前复权；分红单独入账，不重复计算
2. **停牌/涨跌停**：必须带标记，引擎据此拒绝成交
3. **陈旧检测**：`as_of` 落后于最近交易日 → 输出打 `stale: true` 并在脚注说明
4. **限频与重试**：指数退避 ≤3 次；失败返回明确错误码，不返回半截数据
